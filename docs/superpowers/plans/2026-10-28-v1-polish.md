# v1 Polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** External-change detection with hunk-by-hunk merge, clickable encoding / line-ending menus in the status bar, an optional line-number gutter, a font family choice, and wrap off by default.

**Architecture:** Pure logic (line diff, three-way hunk classification, merge, big-diff test, strict decoding) goes in `EditorCore` with swift-testing unit tests. `TextDocument` keeps a *base* text (last loaded/saved), watches the file via NSFilePresenter (`presentedItemDidChange`), and drives a per-tab banner + review sheet in `EditorUI`. Status-bar menus and the gutter are AppKit views wired to `EditorModel`.

**Tech Stack:** Swift 6 tools, AppKit, TextKit 1, swift-testing (`EditorCoreTests`), XCTest (`EditorUITests`). No dependencies.

**Spec:** `docs/superpowers/specs/2026-10-28-v1-polish-design.md`

## Global Constraints

- Swift + AppKit, no dependencies; macOS 14+.
- Never lose the user's unsaved text in any branch of the external-change flow.
- No modal dialog appears on its own while typing; external changes surface as a banner.
- ⌘S (and autosave) never overwrite an unresolved external change.
- Big diff = more than half of the base lines changed.
- Suggested copy name: `<name> (my version).<ext>` next to the original.
- Wrap Lines default **off**; line numbers default **off**; default font SF Mono (system monospaced) 13 pt.
- Font… has no shortcut and offers fixed-pitch families only.
- Encoding list (order): UTF-8, UTF-16 LE, UTF-16 BE, Windows-1251, KOI8-U, KOI8-R, ISO-8859-1, Windows-1252, Mac Roman.
- Run tests with `swift test`; build app with `./scripts/build-app.sh`.

## Review Focus

1. **Our own save echoes back** as `presentedItemDidChange` — no banner, no reload; the disk text equals base after our write.
2. **A log written every second into an edited tab** — banner stays put, no flicker, diffs are coalesced (debounce 0.3 s, cancel in-flight).
3. **Autosave while the banner is up** must not write to disk (autosave in place would otherwise silently overwrite the outside change).
4. **CRLF file changed externally** — diff runs on normalized text, so one changed line is one hunk, not "everything changed".
5. **Undo after Apply / after silent reload** restores the previous text exactly and leaves `LineIndex` consistent with the storage.

Each is pinned by a test in the owning task (Tasks 8–10).

### Task 2: Three-way merge of external changes

**Files:**
- Create: `Sources/EditorCore/ExternalMerge.swift`
- Test: `Tests/EditorCoreTests/ExternalMergeTests.swift`

**Interfaces:**
- Consumes: `normalizedLines`, `LineDiff.hunks`, `DiffHunk` (Task 1).
- Produces:
  - `public struct ExternalHunk: Equatable, Sendable, Identifiable { public let id: Int; public let base: DiffHunk; public let oldLines: [String]; public let isConflict: Bool }` — `id` is stable for identical hunks across re-diffs: hash of `(oldRange, oldLines, newLines)`.
  - `public enum HunkDecision: Sendable { case accept, skip }` — for a conflict, `accept` = take disk, `skip` = keep mine.
  - `public struct ExternalMerge: Sendable`:
    - `public init(base: String, mine: String, disk: String)`
    - `public let hunks: [ExternalHunk]`
    - `public var isBig: Bool` — changed base lines (sum of `oldRange.count`, insertions count as 1) `* 2 > baseLineCount`, or `baseLineCount == 0 && !hunks.isEmpty`.
    - `public var isEmpty: Bool`
    - `public func apply(_ decisions: [Int: HunkDecision]) -> String` — result in LF; missing ids = skip. Caller re-applies the tab's line ending.
- Conflict rule: a base→disk hunk conflicts when its `oldRange` overlaps (or for empty ranges, touches) any base→mine hunk's `oldRange`. Accepting a clean hunk maps its base range into mine via the base→mine hunks' line offsets. Accepting a conflict replaces the overlapping region of mine (union of overlapping base→mine hunks mapped into mine) with `newLines`.

- [ ] **Step 1: Failing tests** (`struct ExternalMergeTests`)
  - `cleanHunkAppliesIntoMyEdits`: base `"a\nb\nc\nd"`, mine `"A\nb\nc\nd"`, disk `"a\nb\nc\nD"` → one hunk, `!isConflict`; `apply([id: .accept]) == "A\nb\nc\nD"`.
  - `skipKeepsMine`: same → `apply([:]) == "A\nb\nc\nd"`.
  - `overlapIsConflict`: base `"a\nb"`, mine `"a\nX"`, disk `"a\nY"` → `isConflict`; accept → `"a\nY"`; skip → `"a\nX"`.
  - `insertionShiftedByMyInsertions`: base `"a\nb"`, mine `"0\na\nb"`, disk `"a\nb\nc"` → accept → `"0\na\nb\nc"`.
  - `idsStableAcrossRediff`: two `ExternalMerge`s with same base/disk, different mine (non-overlapping) → same ids.
  - `bigWhenMoreThanHalfChanged`: base 10 lines, disk changes 6 → `isBig`; changes 5 → `!isBig`.
  - `lineEndingOnlyChangeIsEmpty`: base `"a\nb"`, disk `"a\r\nb"`, mine = base → `isEmpty`.
- [ ] **Step 2:** `swift test --filter ExternalMergeTests` → FAIL.
- [ ] **Step 3: Implement** per the interface and conflict rule above.
- [ ] **Step 4:** run → PASS.
- [ ] **Step 5: Commit** `"Three-way merge of external changes with conflict detection"`
